## The `break` Statement

Exits the innermost loop immediately.

```python
def find_first_even(numbers: list[int]) -> int | None:
    """Finds and returns the first even number in a list."""
    for num in numbers:
        if num % 2 == 0:
            return num  # Essentially a break that returns
    return None

def process_until_stop(commands: list[str]) -> None:
    """Processes commands until 'stop' is encountered."""
    for cmd in commands:
        if cmd == "stop":
            print("Stopping execution.")
            break
        print(f"Processing: {cmd}")

process_until_stop(["start", "run", "stop", "cleanup"])
```

## The `continue` Statement

Skips the rest of the current iteration.

```python
def filter_positive_sums(numbers: list[int]) -> int:
    """Sums only positive numbers, skipping negatives."""
    total: int = 0
    for num in numbers:
        if num < 0:
            continue
        total += num
    return total

print(f"Sum: {filter_positive_sums([3, -1, 5, -2])}")
```

## The `pass` Statement

Does nothing - used as a placeholder. Essential when defining empty classes or handling specific exception cases silently.

```python
class FutureFeature:
    """A class to be implemented in a future release."""
    pass

def handle_errors() -> None:
    """Ignores ValueError explicitly."""
    try:
        int("invalid")
    except ValueError:
        pass  # Explicitly ignore
```

## 🚀 Advanced Topics

### Context Managers and Break Statements
If you use a `break` inside a `with` block (context manager), the context manager's `__exit__` method is still correctly invoked, ensuring cleanup happens safely.

```python
from contextlib import contextmanager
from typing import Iterator

@contextmanager
def temporary_resource() -> Iterator[None]:
    """Demonstrates resource cleanup during loop breaks."""
    print("Resource acquired.")
    try:
        yield
    finally:
        print("Resource released.")

def safe_loop(items: list[str]) -> None:
    """Safely loops and breaks with a resource."""
    for item in items:
        with temporary_resource():
            if item == "quit":
                print("Breaking out!")
                break
            print(f"Using resource for {item}")

safe_loop(["task1", "quit", "task2"])
```

### Asyncio and Break/Continue
When managing `asyncio` tasks, breaking out of an `async for` loop will properly cancel pending awaited items if handled carefully.

```python
import asyncio
from typing import AsyncIterator

async def data_stream() -> AsyncIterator[int]:
    """Generates a stream of data."""
    for i in range(5):
        await asyncio.sleep(0.1)
        yield i

async def consume_stream() -> None:
    """Consumes stream until a condition is met."""
    async for item in data_stream():
        if item == 3:
            print("Target reached, breaking async stream.")
            break
        print(f"Received: {item}")

asyncio.run(consume_stream())
```

### Multithreading and GIL (PEP 703)
In free-threaded Python (PEP 703), breaking out of a loop that is part of a concurrent task queue implies you must manually signal other threads, as one thread breaking does not implicitly stop others. Shared thread-safe flags or event objects must be used to communicate a "break" state across threads.
