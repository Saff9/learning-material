## Creating Tuples (Python 3.12+)

Tuples are immutable sequences, typically used to store collections of heterogeneous data. 

```python
import sys
from typing import Any

# Empty tuple
empty: tuple[()] = ()

# With elements and strict typing
point: tuple[int, int] = (3, 4)

# Single element (note the comma!)
single: tuple[int] = (5,)  # NOT (5) which is just 5

# Without parentheses (Tuple packing)
coordinates: tuple[int, int, int] = 10, 20, 30

# From other iterables
chars: tuple[str, ...] = tuple("hello")  # ('h', 'e', 'l', 'l', 'o')
```

### 🧠 Deep Dive: Memory Profiling

Tuples are more memory-efficient than lists because they are fixed size and don't need over-allocation.

```python
import sys

list_data: list[int] = [1, 2, 3]
tuple_data: tuple[int, int, int] = (1, 2, 3)

print(f"List size: {sys.getsizeof(list_data)} bytes")   # Often 88+ bytes
print(f"Tuple size: {sys.getsizeof(tuple_data)} bytes") # Often 64 bytes
```

## Tuple Immutability

```python
t: tuple[int, int, int] = (1, 2, 3)

# This will ERROR:
# t[0] = 10  # TypeError!

# But mutable elements CAN be modified:
t2: tuple[list[int], list[int]] = ([1, 2], [3, 4])
t2[0].append(3)  # Works! t2 is now ([1, 2, 3], [3, 4])
```

### 🧠 Deep Dive: PEP 703 (GIL / Free-Threading Evolution)
Because tuples are immutable (at the top level), they are inherently thread-safe to share across threads. With Python 3.13+'s experimental free-threading (no GIL, per PEP 703), immutable structures like tuples avoid the locking overhead required for lists or dicts, making them prime candidates for fast, concurrent data sharing.

## Tuple Unpacking

```python
# Basic unpacking
x: int
y: int
x, y = (10, 20)

# Extended unpacking
first: int
rest: list[int]
first, *rest = (1, 2, 3, 4, 5)
# first=1, rest=[2, 3, 4, 5]

first, *middle, last = (1, 2, 3, 4, 5)
# first=1, middle=[2, 3, 4], last=5

# Ignoring values
a: int
b: int
a, _, b = (10, 20, 30)  # a=10, b=30
```

## Named Tuples: `typing.NamedTuple`

In modern Python (3.12+), `typing.NamedTuple` is preferred over `collections.namedtuple` for strict type hinting.

```python
from typing import NamedTuple

class Point(NamedTuple):
    """A 2D Cartesian coordinate."""
    x: int
    y: int

p = Point(3, 4)
print(p.x)  # 3
```

## Advanced Standard Library Integration

### `itertools` and Tuples
```python
import itertools
from typing import Iterator

colors: tuple[str, str] = ("red", "blue")
sizes: tuple[str, str] = ("S", "M")

# Cartesian product returns tuples
combinations: Iterator[tuple[str, str]] = itertools.product(colors, sizes)
print(list(combinations)) 
# [('red', 'S'), ('red', 'M'), ('blue', 'S'), ('blue', 'M')]
```

### `functools.lru_cache` and Tuples
Tuples are hashable (if their contents are hashable), making them perfect keys for dictionaries or arguments for cached functions.

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def expensive_computation(params: tuple[int, int]) -> int:
    """Computes a value based on tuple parameters."""
    return params[0] ** params[1]

print(expensive_computation((2, 10)))  # 1024
```

## Context Managers & Tuples

You can return tuples from custom context managers for clean destructuring.

```python
from contextlib import contextmanager
from typing import Iterator

@contextmanager
def temporary_coordinates(x: int, y: int) -> Iterator[tuple[int, int]]:
    """Context manager yielding a coordinate tuple."""
    print("Setting up coordinates...")
    yield (x, y)
    print("Tearing down coordinates...")

with temporary_coordinates(10, 20) as (cx, cy):
    print(f"Working at {cx}, {cy}")
```

## Async/Await Deep Dive

Many async APIs, such as `asyncio.gather`, are frequently unpacked similarly to tuples, or combined with `tuple()`.

```python
import asyncio
from typing import Any

async def fetch_data(id: int) -> str:
    """Simulates async data fetch."""
    await asyncio.sleep(0.1)
    return f"Data {id}"

async def main() -> None:
    # Gather returns a list, but it's often unpacked as a tuple
    result: tuple[Any, ...] = tuple(await asyncio.gather(
        fetch_data(1),
        fetch_data(2)
    ))
    r1, r2 = result
    print(r1, r2)

# asyncio.run(main())
```

### Exercise 2: Modern NamedTuple Records
```python
from typing import NamedTuple

class Book(NamedTuple):
    title: str
    author: str
    year: int

library: list[Book] = [
    Book("1984", "Orwell", 1949),
    Book("Dune", "Herbert", 1965),
]

for book in library:
    print(f"{book.title} by {book.author} ({book.year})")
```
