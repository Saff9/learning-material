## Log Levels

| Level | Value | When to Use |
|-------|-------|-------------|
| DEBUG | 10 | Detailed information, tracing execution |
| INFO | 20 | General application lifecycle events |
| WARNING | 30 | Unexpected events, but app still runs |
| ERROR | 40 | A function/operation failed |
| CRITICAL | 50 | Serious error, application might crash |

## Basic Configuration

```python
import logging

def configure_basic_logging() -> None:
    """Sets up a basic, global logger."""
    logging.basicConfig(
        level=logging.DEBUG,
        format="%(asctime)s - %(name)s - %(levelname)s - %(message)s",
        datefmt="%Y-%m-%d %H:%M:%S",
        filename="app.log",
        filemode="a"
    )

    logger = logging.getLogger(__name__)
    logger.info("Application started")
    logger.debug("Debug mode is active")
```

## Multiple Handlers (Console & File)
Often, you want detailed logs in a file but only important logs in the console.

```python
import logging

def setup_advanced_logger(name: str) -> logging.Logger:
    """Sets up a logger with a StreamHandler and FileHandler."""
    logger = logging.getLogger(name)
    logger.setLevel(logging.DEBUG) # Lowest level

    # Console handler (WARNING and above)
    console = logging.StreamHandler()
    console.setLevel(logging.WARNING)
    console_format = logging.Formatter("[%(levelname)s] %(message)s")
    console.setFormatter(console_format)

    # File handler (DEBUG and above)
    file_handler = logging.FileHandler(f"{name}.log")
    file_handler.setLevel(logging.DEBUG)
    file_format = logging.Formatter("%(asctime)s - %(name)s - %(levelname)s - %(message)s")
    file_handler.setFormatter(file_format)

    logger.addHandler(console)
    logger.addHandler(file_handler)
    
    return logger

logger = setup_advanced_logger("server_app")
# logger.debug("Only in file")
# logger.warning("In file and console")
```

## 🔬 Deep Dive: functools and Logging Decorators
When writing a decorator to log function calls, you must use `functools.wraps`. This preserves the metadata of the original function (like `__name__` and `__doc__`).

```python
import logging
import functools
from typing import Callable, Any

logging.basicConfig(level=logging.INFO)
module_logger = logging.getLogger(__name__)

def log_calls(logger: logging.Logger = module_logger) -> Callable:
    """A decorator that logs function calls and exceptions."""
    def decorator(func: Callable) -> Callable:
        @functools.wraps(func)
        def wrapper(*args: Any, **kwargs: Any) -> Any:
            logger.info(f"Calling {func.__name__} with args={args}, kwargs={kwargs}")
            try:
                result = func(*args, **kwargs)
                logger.info(f"{func.__name__} returned {result}")
                return result
            except Exception as e:
                logger.error(f"{func.__name__} raised exception: {e}")
                raise
        return wrapper
    return decorator

@log_calls()
def compute_metrics(x: int, y: int) -> int:
    """Computes basic metrics."""
    return x * y
```

## 🔬 Deep Dive: Tracing Logging Overhead with `tracemalloc`
Logging creates strings and string formatting objects. If done inside a tight loop, it can cause memory and CPU overhead. `tracemalloc` helps monitor this.

```python
import logging
import tracemalloc

# Setup a dummy logger
logging.basicConfig(level=logging.ERROR) # Note: level is ERROR
bench_logger = logging.getLogger("benchmark")

def test_logging_overhead() -> None:
    """Traces memory allocation overhead from lazy vs eager logging."""
    tracemalloc.start()
    
    # Eager formatting (BAD: evaluates string even if level is ignored)
    for i in range(100_000):
        bench_logger.debug(f"Process step {i} completed. Memory state XYZ.")
        
    current, peak = tracemalloc.get_traced_memory()
    print(f"Eager Formatting Peak Memory: {peak / 1024 / 1024:.2f} MB")
    tracemalloc.stop()

    tracemalloc.start()
    # Lazy formatting (GOOD: evaluates only if logger level matches)
    for i in range(100_000):
        bench_logger.debug("Process step %s completed. Memory state XYZ.", i)

    current, peak = tracemalloc.get_traced_memory()
    print(f"Lazy Formatting Peak Memory: {peak / 1024 / 1024:.2f} MB")
    tracemalloc.stop()

# test_logging_overhead()
```

## 🔬 Deep Dive: Python GIL, Threading, and Logging
The `logging` module is thread-safe. It uses internal threading locks (`threading.RLock`) to prevent multiple threads from writing to the same log handler simultaneously.

### The GIL (Global Interpreter Lock) and PEP 703
In standard CPython, the GIL prevents multiple native threads from executing Python bytecodes simultaneously. Thus, pure Python log processing never runs in true parallel.
However, with **PEP 703 (Making the Global Interpreter Lock Optional in CPython 3.13+)**, free-threading introduces true multi-threading. The `logging` module's internal locks become critical in free-threaded Python to prevent corrupted log files when dozens of concurrent threads attempt to format and emit logs concurrently.

For high-performance applications, consider `logging.handlers.QueueHandler` and `QueueListener` to offload log formatting and I/O to a dedicated logging thread, preventing blocking on the main application threads.

```python
import logging
import queue
from logging.handlers import QueueHandler, QueueListener

def setup_async_logging() -> QueueListener:
    """Sets up a non-blocking queue-based logger suitable for heavy concurrency."""
    log_queue: queue.Queue = queue.Queue()
    
    # The handler attached to the main loggers
    queue_handler = QueueHandler(log_queue)
    logger = logging.getLogger("async_app")
    logger.addHandler(queue_handler)
    logger.setLevel(logging.INFO)

    # The actual destination (e.g. file or console)
    console_handler = logging.StreamHandler()
    console_handler.setFormatter(logging.Formatter("%(message)s"))
    
    # The listener runs in a separate background thread
    listener = QueueListener(log_queue, console_handler)
    listener.start()
    
    return listener

```
