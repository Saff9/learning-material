## 📖 The Three Streams

Every process in Linux has three default communication channels:

| Stream | File Descriptor | Purpose | Default Connection |
|--------|----------------|---------|-------------------|
| **stdin** | 0 | Input | Keyboard |
| **stdout** | 1 | Normal output | Terminal screen |
| **stderr** | 2 | Error output | Terminal screen |

```
Keyboard -> [stdin 0] -> Process -> [stdout 1] -> Terminal
                                      |
                                      +-> [stderr 2] -> Terminal
```

---

## 🔢 File Descriptors

File descriptors are numbers that identify open files/streams:

```bash
# See file descriptors of current shell
ls -la /proc/$$/fd

# Output:
# lrwx------ 1 user user 64 Jul 15 10:00 0 -> /dev/pts/0
# lrwx------ 1 user user 64 Jul 15 10:00 1 -> /dev/pts/0
# lrwx------ 1 user user 64 Jul 15 10:00 2 -> /dev/pts/0
# lr-x------ 1 user user 64 Jul 15 10:00 255 -> /dev/pts/0
```

| FD | Name | Default |
|----|------|---------|
| 0 | stdin | Keyboard |
| 1 | stdout | Terminal |
| 2 | stderr | Terminal |
| 3+ | Custom | Files, pipes, sockets |

## ➡️ Redirection

Redirection changes where streams go.

### Output Redirection (>)

```bash
# Redirect stdout to file (OVERWRITES!)
echo "Hello" > file.txt

# Redirect stdout to file (APPENDS)
echo "World" >> file.txt

# Using file descriptor explicitly
echo "Hello" 1> file.txt
```

### Input Redirection (<)

```bash
# Feed file content as stdin
cat < file.txt

# Same as:
cat file.txt

# But useful for commands that only read stdin
sort < unsorted.txt > sorted.txt
```

### Error Redirection (2>)

```bash
# Redirect errors to file
command 2> errors.log

# Redirect output and errors to different files
command > output.log 2> errors.log

# Redirect errors to stdout
command 2>&1

# Redirect stdout to stderr
echo "Error message" 1>&2
```

## 🔀 Combining Streams

### Redirect Both to Same File

```bash
# Method 1: Old style
command > file.txt 2>&1

# Method 2: Bash 4+ shorthand
command &> file.txt

# Append both
command &>> file.txt
```

**Order matters!**
```bash
# CORRECT: stdout to file, stderr to where stdout goes
command > file.txt 2>&1

# WRONG: stderr goes to current stdout (terminal), then stdout to file
command 2>&1 > file.txt
```

### Discard Output

```bash
# Discard stdout
command > /dev/null

# Discard stderr
command 2> /dev/null

# Discard everything
command > /dev/null 2>&1
# or
command &> /dev/null
```

### Swap stdout and stderr

```bash
# Swap stdout (1) and stderr (2)
command 3>&1 1>&2 2>&3
```

## 📊 Visual Redirection Guide

```bash
# Basic output redirection
echo "text" > file
# stdin(0) -> [echo] -> stdout(1) -> file

# Basic input redirection
cat < file
# file -> stdin(0) -> [cat] -> stdout(1) -> terminal

# Error redirection
command 2> error.log
# stdin(0) -> [command] -> stdout(1) -> terminal
#                          stderr(2) -> error.log

# Both to same file
command > all.log 2>&1
# stdin(0) -> [command] -> stdout(1) -> all.log
#                          stderr(2) -> all.log (same as stdout)

# Pipe (connect stdout to stdin of next command)
cat file | grep "pattern"
# file -> stdin(0) -> [cat] -> stdout(1) -> stdin(0) -> [grep] -> stdout(1) -> terminal
```

## 🧪 Practice

```bash
# 1. Create a file with output
echo "Line 1" > test.txt
echo "Line 2" >> test.txt

# 2. Redirect errors
ls /nonexistent 2> error.txt
cat error.txt

# 3. Redirect both output and error
ls /nonexistent /home > output.txt 2> error.txt

# 4. Redirect both to same file
ls /nonexistent /home > all.txt 2>&1

# 5. Discard all output
find / -name "*.log" > /dev/null 2>&1

# 6. Count lines from stdin
wc -l < /etc/passwd

# 7. Here document
cat << EOF
This is a here document.
It can span multiple lines.
Variables work: $HOME
EOF

# 8. Here string
cat <<< "Hello from here string"
```
