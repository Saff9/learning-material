## What are Virtual Environments?

Virtual environments are isolated Python environments. They maintain their own independent set of installed Python packages and standard library references, keeping your global Python installation clean and preventing dependency conflicts between projects.

## Creating a Virtual Environment

```bash
# Create environment named 'venv'
python -m venv venv

# Create environment, but inherit system site-packages (rarely recommended)
python -m venv venv --system-site-packages
```

## Activating the Environment

```bash
# Linux/Mac
source venv/bin/activate

# Windows (Command Prompt)
venv\Scripts\activate.bat

# Windows (PowerShell)
venv\Scripts\Activate.ps1
```

## Working with Environments

```bash
# After activation, pip installs ONLY into the virtual environment
pip install requests numpy

# Check installed packages
pip list

# Check which python executable is running
# Unix: which python
# Windows: where python
```

## 💻 Programmatic Environment Management

### Creating Environments in Python Code (Python 3.12+)

```python
"""Virtual environment management with strict typing."""
import os
import sys
import venv
from pathlib import Path
from typing import Optional

def create_project_env(env_dir: Path) -> None:
    """
    Programmatically creates a virtual environment using the built-in venv module.
    """
    print(f"Creating virtual environment at {env_dir}...")
    
    # The venv.create method is safer and cleaner than subprocess calls
    venv.create(
        env_dir=env_dir,
        system_site_packages=False,
        clear=True,
        with_pip=True
    )
    print("Environment created successfully.")

if __name__ == "__main__":
    target_dir: Path = Path("my_project_env")
    create_project_env(target_dir)
```

## 🧪 Practice

### Exercise 1: Asynchronous Environment Setup Script
Sometimes you want to set up an environment and install packages without blocking the main event loop.

```python
import asyncio
import os
import sys
from pathlib import Path
from typing import List, Optional

async def async_install(env_python: Path, package: str) -> bool:
    """Installs a package asynchronously into the specified environment."""
    print(f"Installing {package}...")
    process = await asyncio.create_subprocess_exec(
        str(env_python), "-m", "pip", "install", package,
        stdout=asyncio.subprocess.PIPE,
        stderr=asyncio.subprocess.PIPE
    )
    
    stdout, stderr = await process.communicate()
    if process.returncode == 0:
        print(f"Success: {package}")
        return True
    
    print(f"Failed to install {package}:\n{stderr.decode()}")
    return False

async def setup_async_project(project_name: str, packages: list[str]) -> None:
    """Creates a venv and installs packages concurrently."""
    project_dir = Path(project_name)
    project_dir.mkdir(exist_ok=True)
    
    env_dir = project_dir / "venv"
    # Note: venv creation is sync, but fast enough for script usage
    import venv
    venv.create(env_dir, with_pip=True)
    
    # Determine python path depending on OS
    if os.name == "nt":
        env_python = env_dir / "Scripts" / "python.exe"
    else:
        env_python = env_dir / "bin" / "python"
        
    print(f"Using isolated Python: {env_python}")
    
    tasks = [
        asyncio.create_task(async_install(env_python, pkg))
        for pkg in packages
    ]
    
    results: list[bool] = await asyncio.gather(*tasks)
    if all(results):
        print(f"Project {project_name} fully configured!")

if __name__ == "__main__":
    asyncio.run(setup_async_project("async_test_project", ["requests", "rich"]))
```

## ✅ Check Your Understanding

1. **What is a virtual environment?**
   - An isolated Python context to prevent package version conflicts across projects.
2. **How do you programmatically create a venv in modern Python without using `subprocess`?**
   - By using the built-in `venv.create()` module function.
3. **Where are packages installed in a venv?**
   - In the venv's `lib/pythonX.Y/site-packages` (Unix) or `Lib/site-packages` (Windows) directory.
4. **Why do we need `with_pip=True` when creating a venv via code?**
   - So that the virtual environment includes the pip package manager, enabling us to install third-party libraries later.
