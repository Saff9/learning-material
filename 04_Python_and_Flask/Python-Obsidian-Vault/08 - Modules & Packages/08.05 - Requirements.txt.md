## Basic Requirements File

```text
# requirements.txt
requests
numpy
pandas
flask
```

## Version Specifiers

```text
# Exact version (Pinned for reproducibility)
requests==2.31.0

# Minimum version (Ensures bug fixes are included)
requests>=2.31.0

# Compatible release (Same major version, allows minor/patch updates)
requests~=2.31.0

# Range
requests>=2.27.0,<3.0.0

# No version (Latest - NOT recommended for production)
requests
```

## Generating Requirements

```bash
# Generate from current environment
pip freeze > requirements.txt

# Extract names only (Unix)
pip freeze | sed 's/==.*//' > requirements.txt
```

## Installing from Requirements

```bash
pip install -r requirements.txt

# With specific index (useful for corporate networks)
pip install -r requirements.txt --index-url https://pypi.org/simple
```

## Best Practices

Split requirements by environment:

```text
# requirements.txt - Production dependencies
flask==3.0.0
requests==2.31.0

# requirements-dev.txt - Development dependencies
-r requirements.txt
pytest==7.4.0
black==23.7.0
flake8==6.1.0
```

## 💻 Programmatic Requirements Management

### Context Managers for Safe Parsing

Always use the `with` statement context manager when reading files to ensure resources are released immediately, even if exceptions occur.

```python
"""Parsing requirements with context managers and strict types."""
from pathlib import Path
from typing import List

def parse_requirements(filepath: Path) -> list[str]:
    """
    Safely parses a requirements file.
    
    Args:
        filepath: The path to the requirements file.
        
    Returns:
        A list of clean package requirement strings.
    """
    requirements: list[str] = []
    
    if not filepath.exists():
        raise FileNotFoundError(f"{filepath} not found.")
        
    # The context manager ensures the file is closed reliably
    with filepath.open(mode="r", encoding="utf-8") as file:
        for line in file:
            clean_line: str = line.strip()
            # Ignore empty lines and comments
            if clean_line and not clean_line.startswith("#"):
                requirements.append(clean_line)
                
    return requirements

if __name__ == "__main__":
    req_file: Path = Path("requirements.txt")
    # Only run if file exists for demo purposes
    if req_file.exists():
        parsed: list[str] = parse_requirements(req_file)
        print("Parsed Requirements:", parsed)
```

### Exercise 1: Asynchronous Requirement Verification
Verifying if required versions match installed versions.

```python
import importlib.metadata
import asyncio
from typing import Dict

async def verify_package_async(requirement: str) -> bool:
    """
    Asynchronously verify if a package from requirements 
    is installed in the current environment.
    (Simplified version checker that just checks existence).
    """
    # Extract package name before any specifier like == or >=
    pkg_name: str = requirement.split("=")[0].split(">")[0].split("<")[0].split("~")[0]
    
    # Simulate async delay if we were checking against PyPI
    await asyncio.sleep(0.05)
    
    try:
        version = importlib.metadata.version(pkg_name)
        print(f"✅ {pkg_name} is installed (version {version})")
        return True
    except importlib.metadata.PackageNotFoundError:
        print(f"❌ {pkg_name} is MISSING")
        return False

async def main_verifier(reqs: list[str]) -> None:
    """Verifies all requirements concurrently."""
    tasks = [asyncio.create_task(verify_package_async(req)) for req in reqs]
    results: list[bool] = await asyncio.gather(*tasks)
    
    if all(results):
        print("All requirements met!")
    else:
        print("Some requirements are missing. Please run `pip install -r requirements.txt`")

if __name__ == "__main__":
    # Simulating parsed requirements
    sample_requirements: list[str] = ["pip", "setuptools"]
    asyncio.run(main_verifier(sample_requirements))
```

## ✅ Check Your Understanding

1. **What is requirements.txt for?**
   - It lists project dependencies and their versions to ensure reproducible environments.
2. **What does `==` mean in requirements?**
   - Exact version required (pinning).
3. **What does `~=` mean?**
   - Compatible release (e.g., `~=2.31.0` allows `2.31.x` but not `2.32.0`).
4. **Why is using a context manager (`with open(...) as f:`) important when reading files?**
   - It ensures that the file descriptor is safely closed immediately after reading, preventing resource leaks.
