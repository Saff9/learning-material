## Creating Custom Exceptions

```python
from typing import Any

class ValidationError(Exception):
    """Raised when input validation fails."""
    pass

class InvalidAgeError(Exception):
    """Raised when age is outside valid boundaries."""
    
    def __init__(self, age: int, message: str = "Age must be between 0 and 150") -> None:
        """
        Initializes the exception with the invalid age and a message.
        """
        self.age: int = age
        self.message: str = message
        super().__init__(self.message)

    def __str__(self) -> str:
        return f"{self.message}. Got: {self.age}"

def validate_age(age: int) -> int:
    """Validates user age."""
    if age < 0 or age > 150:
        raise InvalidAgeError(age)
    return age
```

## Exception Hierarchy
Defining a base exception for your application/library makes it easier for users to catch all related errors.

```python
class AppError(Exception):
    """Base exception for our application."""
    pass

class DatabaseError(AppError):
    """Database related errors."""
    pass

class ConnectionError(DatabaseError):
    """Connection specific errors."""
    pass

def connect_to_db() -> None:
    raise ConnectionError("Failed to establish TCP connection")

try:
    connect_to_db()
except DatabaseError as e:
    # Catches ConnectionError and any other subclass of DatabaseError
    print(f"Database issue: {e}")
```

## Adding Notes to Exceptions (Python 3.11+)
Python 3.11 allows enriching exceptions with `.add_note()` without needing to subclass or modify the exception message itself.

```python
def process_data(data: dict[str, Any]) -> None:
    """Processes data and adds context to exceptions on failure."""
    try:
        user_id = data["user_id"]
        # Risky operation here
        raise ValueError("Invalid user_id format")
    except KeyError as e:
        e.add_note(f"Missing required key in data dictionary. Received keys: {list(data.keys())}")
        raise
    except ValueError as e:
        e.add_note(f"Validation failed for user mapping. Payload: {data}")
        raise

try:
    process_data({"username": "alice"})
except Exception as e:
    print(f"Error caught: {e}")
    if hasattr(e, '__notes__'):
        print(f"Notes attached: {e.__notes__}")
```

## 🧪 Practice

### Exercise 1: Config Validator
A practical example showing a well-structured exception hierarchy.

```python
from typing import Any

class ConfigError(Exception):
    """Base class for configuration errors."""
    pass

class MissingKeyError(ConfigError):
    """Raised when a required key is missing."""
    def __init__(self, key: str) -> None:
        self.key = key
        super().__init__(f"Missing required key: {key}")

class InvalidValueError(ConfigError):
    """Raised when a value has the wrong type or bounds."""
    def __init__(self, key: str, value: Any, expected: str) -> None:
        self.key = key
        self.value = value
        self.expected = expected
        super().__init__(f"Invalid value for '{key}': {value} (type: {type(value).__name__}). Expected: {expected}")

def validate_config(config: dict[str, Any]) -> bool:
    """Validates configuration dictionary."""
    required_keys: list[str] = ["host", "port", "username"]
    
    for key in required_keys:
        if key not in config:
            raise MissingKeyError(key)

    if not isinstance(config["port"], int):
        raise InvalidValueError("port", config["port"], "integer")

    return True

try:
    validate_config({"host": "localhost", "port": "8080", "username": "admin"})
except ConfigError as e:
    print(e)
```

## ✅ Check Your Understanding

1. What should custom exceptions inherit from?
2. Why should a project define a base exception class (like `AppError`)?
3. What is the purpose of `__init__` and `__str__` in custom exceptions?
4. What does `.add_note()` (Python 3.11+) do?
5. When should you create custom exceptions?

**Answers:**
1. `Exception` (or a more specific built-in like `ValueError`). Rarely `BaseException`.
2. It allows users of your code to catch all errors originating from your module with a single except block.
3. `__init__` sets up custom attributes for debugging, while `__str__` formats the error message for users.
4. It attaches extra contextual strings to an exception traceback without rewriting the original error.
5. When built-in exceptions don't describe the failure domain properly, or when you need callers to differentiate between specific error states.
