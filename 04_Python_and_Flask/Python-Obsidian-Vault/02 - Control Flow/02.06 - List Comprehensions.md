## Basic List Comprehension

```python
def generate_squares(limit: int) -> list[int]:
    """Generates a list of squares using comprehension."""
    return [x ** 2 for x in range(limit)]

print(generate_squares(5))
```

## With Condition (Filter)

```python
def filter_evens(numbers: list[int]) -> list[int]:
    """Filters only even numbers."""
    return [x for x in numbers if x % 2 == 0]

print(filter_evens([1, 2, 3, 4, 5, 6]))
```

## Dictionary and Set Comprehension

```python
def create_length_dict(words: list[str]) -> dict[str, int]:
    """Creates a mapping of words to their lengths."""
    return {word: len(word) for word in words}

def get_unique_lengths(words: list[str]) -> set[int]:
    """Creates a set of unique lengths."""
    return {len(word) for word in words}

sample_words: list[str] = ["apple", "banana", "cherry", "date"]
print(create_length_dict(sample_words))
print(get_unique_lengths(sample_words))
```

## 🚀 Advanced Topics

### Generator Expressions and Memory Profiling (`tracemalloc`)
List comprehensions build the entire list in memory. For massive datasets, generator expressions `(...)` evaluate lazily, saving RAM. We can prove this using `tracemalloc`.

```python
import tracemalloc

def profile_comprehension_vs_generator() -> None:
    """Profiles the memory difference between list comp and generator."""
    limit = 1_000_000
    
    # Profile List Comprehension
    tracemalloc.start()
    list_comp: list[int] = [x**2 for x in range(limit)]
    current_list, peak_list = tracemalloc.get_traced_memory()
    tracemalloc.stop()
    del list_comp
    
    # Profile Generator Expression
    tracemalloc.start()
    gen_expr = (x**2 for x in range(limit))
    current_gen, peak_gen = tracemalloc.get_traced_memory()
    tracemalloc.stop()
    
    print(f"List Comp Peak Memory: {peak_list / 10**6:.2f} MB")
    print(f"Generator Peak Memory: {peak_gen / 10**6:.2f} MB")

profile_comprehension_vs_generator()
```

### Async Comprehensions
Python supports async comprehensions to gather results from asynchronous iterators or awaitables.

```python
import asyncio
from typing import AsyncIterator

async def async_range(limit: int) -> AsyncIterator[int]:
    """An asynchronous generator."""
    for i in range(limit):
        await asyncio.sleep(0.01)
        yield i

async def process_async_data() -> None:
    """Uses async comprehensions to process data."""
    # Async list comprehension
    results: list[int] = [x * 2 async for x in async_range(5)]
    print(results)
    
    # Awaiting inside a comprehension
    async def fetch_val(v: int) -> int:
        await asyncio.sleep(0.01)
        return v * 10
        
    tasks_results: list[int] = [await fetch_val(x) for x in range(5)]
    print(tasks_results)

asyncio.run(process_async_data())
```

### Flattening with `itertools` vs Nested Comprehension
Nested comprehensions can get hard to read. Standard library tools like `itertools.chain` are often faster and cleaner in CPython.

```python
import itertools

def flatten_matrix(matrix: list[list[int]]) -> list[int]:
    """Compares nested comprehensions and itertools."""
    # Nested comprehension
    flat_comp: list[int] = [item for row in matrix for item in row]
    
    # itertools approach (often faster and lower memory overhead)
    flat_iter: list[int] = list(itertools.chain.from_iterable(matrix))
    
    return flat_iter

print(flatten_matrix([[1, 2], [3, 4]]))
```

### Performance, Collections, and GIL (PEP 703)
Comprehensions are implemented in C under the hood, making them significantly faster than equivalent `for` loops appending to a list. Because they run highly optimized bytecodes (e.g. `LIST_APPEND`), they hold the GIL tightly during execution. 
In multithreaded workflows (pre-PEP 703), a massive comprehension will block other Python threads. With PEP 703 (free-threading), massive comprehensions isolated in threads will scale beautifully across CPU cores without blocking execution. For high-performance aggregation, `collections.deque` can be faster than list appending if you only need iteration and pop semantics.
