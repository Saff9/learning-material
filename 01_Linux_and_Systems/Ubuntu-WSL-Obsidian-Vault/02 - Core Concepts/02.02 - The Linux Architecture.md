## 🧠 The Kernel

The **kernel** is the core of Linux. It manages:

| Subsystem | Responsibility |
|-----------|---------------|
| **Process Management** | Creating, scheduling, terminating processes |
| **Memory Management** | Allocating RAM, virtual memory, swap |
| **File Systems** | Reading/writing files, permissions |
| **Device Drivers** | Talking to hardware |
| **Networking** | TCP/IP, sockets, interfaces |
| **Security** | Permissions, SELinux/AppArmor, capabilities |

### Kernel Space vs User Space

```
+----------------------------------+
|         Kernel Space              |  <- Ring 0 (highest privilege)
|  - Direct hardware access         |
|  - Memory management              |
|  - Process scheduling             |
+----------------------------------+
|         User Space                |  <- Ring 3 (restricted)
|  - Your applications              |
|  - Shell commands                 |
|  - Cannot access hardware directly|
+----------------------------------+
```

> **Analogy:** The kernel is like the operating system of a building — it controls the elevators, electricity, water. Your apartment (user space) requests services but can't directly flip the main breaker.

## 📞 System Calls

Programs in user space can't directly access hardware. They ask the kernel through **system calls**.

### Common System Calls

| System Call | What It Does              | Shell Equivalent              |
| ----------- | ------------------------- | ----------------------------- |
| `read()`    | Read from file descriptor | `cat file`                    |
| `write()`   | Write to file descriptor  | `echo > file`                 |
| `open()`    | Open a file               | Opening a file in any program |
| `close()`   | Close a file descriptor   | —                             |
| `fork()`    | Create a new process      | Running a command             |
| `exec()`    | Execute a program         | Running a command             |
| `exit()`    | Terminate a process       | `exit` command                |
| `kill()`    | Send signal to process    | `kill` command                |
| `mmap()`    | Map file to memory        | Memory-mapped files           |
| `socket()`  | Create network socket     | Network connections           |

### Watching System Calls

```bash
# Trace system calls of a command
strace ls

# Trace system calls of a running process
strace -p 1234

# Count system calls
strace -c ls
```

**Example strace output:**

## 🔄 The Boot Process

When you start your computer (or WSL):

```
1. BIOS/UEFI    -> Hardware initialization
       |
2. Bootloader   -> GRUB loads (or WSL init)
       |
3. Kernel       -> Linux kernel loads into memory
       |
4. init/systemd -> First process (PID 1) starts
       |
5. Services     -> Networking, logging, etc. start
       |
6. Login        -> Shell starts for user
       |
7. User Space   -> Your applications run
```

### WSL Boot Process

WSL is different from a physical machine:

```
Windows starts
    |
WSL service starts (wsl.exe)
    |
Lightweight VM boots (WSL2)
    |
Linux kernel loads
    |
init process starts (systemd or init)
    |
User shell starts
```

```bash
# See the init process
ps -p 1
# PID TTY      STAT   TIME COMMAND
#   1 ?        Ss     0:00 /sbin/init

# In modern Ubuntu WSL, this might be systemd
# Check with:
ps -p 1 -o comm=
```

## 🧩 Userspace Components

### init / systemd (PID 1)

The first process that starts all others.

```bash
# Check if systemd is running
systemctl --version

# List all services
systemctl list-units --type=service

# Check service status
systemctl status ssh
```

### System Libraries

Shared libraries that programs use:

```bash
# See shared libraries a program uses
ldd /bin/ls

# Output:
# linux-vdso.so.1 (0x00007fff...)
# libselinux.so.1 => /lib/x86_64-linux-gnu/libselinux.so.1
# libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6
```

### Shell

Your command interpreter:

```bash
# Check your shell
echo $SHELL

# Check shell version
bash --version
```

## 🧪 Practice

```bash
# 1. See your process tree
pstree -p $$

# 2. Trace system calls of 'ls'
strace -e trace=openat,read,write ls

# 3. See what libraries 'ls' uses
ldd /bin/ls

# 4. Check init process
ps -p 1 -f

# 5. See kernel version
uname -a

# 6. See loaded kernel modules
lsmod

# 7. Check if systemd is PID 1
systemctl is-system-running
```
